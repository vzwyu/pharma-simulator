## 《上量》内资药企营销模拟游戏（新区块，已完成 v1）

**位置**
- 源码：`src/`（`index.html` / `style.css` / `js/data.js` / `js/engine.js` / `js/ui.js`）
- 构建：`python build.py` → `dist/上量.html`（单文件，约 118 KB，零外部依赖，可 file:// 直开）
- 无头数值测试：`node test/sim3.js`（全流程 4 幕跑通）；`test/sim.js` 对比稳健 vs 带金两条路径

**设计要点（后续迭代别推翻）**
- 四幕：县域（青阳，6 终端，目标 38 万）→ 地市（云州，10 终端，110 万）→ 省区（8 地市，450 万）→ 全国（6 大区，2000 万）。编制 6/10/15/22。
- 销售模型：`份额 = base + 认知×0.26×品种权重 + 覆盖×0.135 + 客情×0.11 - 竞品×0.16 + 价格差`，再乘 `准入系数(0.02+0.98×(access/100)^0.7)` 和打法系数。
- 精力 = 3 + 下属数 × 0.4（上限 9），每月结算后补满。
- 经济：销售额 × 45% 进费用池，扣人力成本；预算上限 `max(120, 目标×2.5)`，超出上缴。
- 合规：每个代表独立 `exposure`，打法按 `exposure/月` 累积（压货 4 / 统方 9 / 带金 15），阈值 18 约谈、40 解聘、55 停采、75 司法；检查概率 `0.015 + (risk/100)²×0.5`。
- 打法系数 `mul`：带金 1.32、统方 1.16、压货 1.06——这是让"带金短期确实更快"的关键，不能删。

**已验证的平衡**
- 合规路线：第 7 个月左右晋升，全程 33 个月通关。
- 带金路线：前 5 个月销售高 30%+，第 11、14、16 月连续被查，第 16 月免职出局。

**踩过的坑**
- `apMax` 未在月末重置导致后续月份无行动点，数值全平——已修。
- 促销/招聘里重置 AP 会被玩家利用刷精力，已移除。
- 环比口径曾误用"月初预计 vs 月末实际"，现改为对比 `history` 上月实际值，首月显示"首月"。

**未做 / 可加**
- 品种详情页、终端排序筛选、结算动画、音效。
- 目前 30+ 回合全靠点击项目，后续可考虑批量排期。

## v2 改版（15:47–16:10）

**改名**：上量 → 药企模拟器 / Pharma Simulator。产物 `dist/药企模拟器.html`（build.py 输出路径已改）。

**数据模型变更（重点，别改回去）**
- 代表从 `r.terminal` 单店改为 `r.assign = { 终端id: { p:[品种id], pharm:bool } }`。
- **一个「终端 × 品种」格子只归一名代表**（`setCellRep`），后写覆盖先写；院边药店同理（`setPharmRep`）。
- 管理当量：医院 1.0 / 基层 0.5 / 连锁 0.7，每多一个品种 +0.08，承接院边药店 +0.12，医共体每多一家成员 +0.2；上限 `CFG.repCap = 2.0`，超载按 `(cap/L)^0.6` 衰减。
- 覆盖：`pw = base * (w/L) * overload`，base = ability/100 × 角色系数 × 士气 × 打法系数。
- 医共体：`ALLIANCES[act]` 定义，同一代表覆盖 ≥2 成员 → `allyMul = 1+0.06*(n-1)`（上限 1.15），开发时也乘这个系数。
- 院边药店：医院代表承接后，连锁终端 `retailEff = stores / max(stores*0.4, stores-pharmTaken)`，上限 1.8。
- 终端新增 `spend`（累计投入），launchProject 按终端数平摊记账；UI 展示 产出/投入/费效（产出×12/投入）。

**项目系统**
- 每个项目有 `fail`（基础失败率）与 `delay`（延迟月数）；`failRateOf` 叠加客情、竞品、监管压力、医共体协同、是否有代表。
- 延迟项目进 `S.pending`，结算时 `resolvePending()` 在月初结算，结果写进月报 `resolved`。
- 多终端：`launchProject(pid, [tids])`，成本线性叠加，精力 `ap + floor((n-1)/2)`。

**管理事件**
- `MGMT_EVENTS` 6 个（网格化/费用压缩/备案/承诺书/周报抽查/轮岗），统一三档 严格执行/选择执行/不执行。
- 不执行会写 `flags.auditAt`，2–3 个月后 `rollEvent` 强制弹出 `AUDIT_EVENT` 专项核查。

**UI**
- 团队页：多选下拉（popover）选终端 + chip 展示 + 管理当量条。
- 「团队明细配置」弹窗：终端 × 品种矩阵，**格子里直接下拉选人**，不同代表不同颜色（REP_COLORS 8 色），列含 本月产出 / 累计投入 / 费效。
- 行动页：多选终端的弹窗，实时显示成本、精力、平均失败率、生效时间。

## v3：标签体系（16:58）

- 废弃 `TRAITS`，改为 `VISIBLE_TAGS`（8 个，每人 1–2 个）+ `HIDDEN_TAGS`（10 个，每人 1–3 个，卡片只显示「未知 ×N」）。
- 代表带 `r.tags` / `r.hidden` / `r.mod`（所有标签效果求和）。mod 键位：
  `cap/cov/aw/rel/ct/growth/salary/exposure/fail/ally/loyalty0/loyalty/rebate/jobhunt`。
- **管理当量上限改为 per-rep**：`repCapOf(r) = clamp(2.0 + mod.cap, 0.8, 4)`。实测分布 1.3–3.4，中位数 2.0；拼命三郎 2.7、应届生 1.5、铁人+拼命三郎 3.1。
- 生效点：repBase 乘 (1+cov)、认知/客情乘 (1+aw/rel)、exposure 乘 (1+exposure)、
  忠诚每月加 mod.loyalty（jobhunt 满 10 月额外 -2.2）、失败率加 mod.fail、医共体倍率加 mod.ally、
  带金收益乘 (1+mod.rebate)、薪资乘 (1+mod.salary)。
- UI：卡片显示可见标签 chip（title 为说明）+「未知 ×N」虚线 chip；团队页底部加「可见标签图鉴」。
- `test/tags.js` 可查分布与单标签对照。

## v4：猜标签（17:18）

- 本地人从隐藏移入可见标签（9 个可见）；隐藏池扩到 20 个。
- 新增 `guessTag(rid, tagId)`：每人最多 2 次、每次 1 精力。猜中 → 标签转「已确认」，
  `mod.cap += 0.25`、`mod.cov += 0.05`、`mod.aw += 0.05`；猜错 → `mod.cov -= 0.06`、忠诚 -7。
- `observations(r)` 只取**隐藏标签**的效果做阈值判断，输出「现象」不给标签名（否则会被可见标签污染）。
  阈值：cap≤-0.15 / cov≤-0.03 或 ≥0.04 / fail≥0.04 / 忠诚类需在岗≥3 月 / jobhunt 需≥8 月。
- 已校验 20 个隐藏标签每个都至少产出 1 条观察线索。
- UI：代表卡加「观察」条 + 「猜标签」按钮；弹窗 20 宫格，已猜过的置灰「猜过·未中」。
